# v0.1.0

First public alpha of Trisynapse Memory: a local-first Trace & Recall engine that stores source evidence, retrieves the useful parts, and answers with citations.

## ✨ Highlights

- One engine shared by Python, the `trisynapse-memory` CLI, REST, Memory Studio, and the TypeScript client.
- Unified ingestion for conversations, documents, code, web pages, tables, images, and structured records.
- Grounded answers that cite Trace evidence, or abstain when confidence is too low.

## 🚀 New Features

- **Python API.** `MemoryEngine` can add observations, ingest mixed sources, search, query, forget, and physically remove memory in a namespace.
- **CLI and terminal.** `trisynapse-memory` initializes a local store, ingests sources, searches and queries, and opens an interactive terminal when run with no arguments.
- **REST API and Memory Studio.** `trisynapse-memory serve --studio` exposes the same store over HTTP, with Studio for sources, queries, memory graphs, and model settings.
- **TypeScript client.** `@trisynapse/memory` talks to a local or remote server with typed helpers for health, memory, search, and query.
- **Source pipeline.** Files, directories, archives, Git URLs, public web pages, and images (through a vision-capable completion model) keep locators such as pages, symbols, line ranges, rows, and cells.
- **Providers.** Local embeddings work with no completion API key. Optional completion providers support generation and image understanding.
- **Operations.** Backup, restore, durable ingestion jobs, snapshots, store verification, and installer scripts for macOS, Linux, and Windows.

## 🐛 Bug Fixes

- Fixed Memory Studio fallback when the built UI assets are missing.
- Fixed macOS installer variable expansion so the POSIX installer can resolve the published package version.

## 📦 Other Changes

- Release workflow builds and publishes `trisynapse-memory==0.1.0` to PyPI and attaches installers, checksums, and `release.json` to the GitHub release.
