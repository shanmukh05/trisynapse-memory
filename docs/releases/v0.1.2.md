# v0.1.2

This release replaces hash-chain “verification” with store validation, adds profiled and token-aware retrieval, and publishes the TypeScript client as `@trisynapse/trisynapse-memory`. Existing 0.1.x stores migrate automatically; several CLI, REST, and SDK names change.

## ✨ Highlights

- Retrieval can pick a profile, enable specific routes, and budget answer context by tokens instead of item count alone.
- `verify` / `verify_trace()` become `validate` / `validate_store()`, which check SQLite, sequence continuity, and retained source blobs.
- The TypeScript package is renamed and published to npm as `@trisynapse/trisynapse-memory`.

## 🚀 New Features

- **Retrieval profiles and routes.** Configuration now includes `retrieval_profile`, `enabled_routes`, and `route_weights`. Profiles include `auto`, `balanced`, `precise`, `broad`, `mixed`, `code`, `table`, `image`, `document`, and `conversation`. Python callers can supply a `QueryPlanner` and `RouteRegistry`.
- **Token-aware grounding.** `max_context_tokens` and `per_source_context_tokens` cap how much evidence enters an answer. Optional `tiktoken` extra and `token_counter_for()` provide model-aware counting; applications can pass a custom `TokenCounter`.
- **Richer observations.** REST and the TypeScript client accept `modality`, `source_type`, and `retrieval_fields` on observation writes. Search hits include locators, confidence, temporal anchors, and metadata.
- **Benchmark controls.** `trisynapse-memory bench run` and the REST benchmark API accept `sampling` (`auto`, `stratified`, `sequential`) and an optional independent judge model.
- **npm publishing.** Tagged releases publish `@trisynapse/trisynapse-memory` (prereleases get the `next` tag) and smoke-test an exact-version install.

## 🔧 Improvements

- Lexical search tokenizes Unicode prose, code identifiers, and CJK text without a language-specific segmenter.
- Query planning recognizes multi-hop questions in addition to fact, temporal, list, and inference.
- CLI long-running work shows progress; pass `--no-progress` to disable it.
- The interactive terminal runs ingestion, search, query, and model actions without freezing the UI, and streams query stages as they complete.
- Studio retrieval settings expose profile and token-budget controls. Health copy now reports store readiness instead of “Trace verified.”
- Release asset lists stay limited to installers, distributions, checksums, and `release.json`.

## 🐛 Bug Fixes

- Query answers reject malformed citation ID lists instead of accepting an invalid grounded response.

## ⚠️ Breaking Changes

- **CLI:** `trisynapse-memory verify` is now `trisynapse-memory validate`.
  - **Migration:** Update scripts and docs to call `validate`.
- **Python:** `MemoryEngine.verify_trace()` is now `validate_store()`. `TraceVerification` is now `StoreValidation`. `PrivacyFilter` and `RedactionResult` are no longer exported. `__version__` still comes from `trisynapse_memory`, but `trisynapse_memory._version` is gone.
  - **Migration:** Switch to `memory.validate_store()`. Import planner/route/token types from `trisynapse_memory`. Do not import deleted modules such as `engine.privacy`, `engine.trace` (the old module), or `_version`.
- **REST / Studio / JS health:** `trace_valid` is now `storage_ready`. `/api/v1/check` and `/api/v1/metrics` no longer return a full trace-verification object.
  - **Migration:** Read `storage_ready`. Use `validate_store()` / `GET /api/v1/check` for the new `StoreValidation` fields.
- **Trace records:** Deltas are no longer hash-chained. `MemoryDelta` no longer includes `prev_hash` or `hash`. `RemoveResult` no longer includes `old_root_hash` or `new_root_hash`. `privacy_scope` remains only for store compatibility and does not filter.
  - **Migration:** Open the store with 0.1.2; the engine drops legacy chain columns. Stop depending on root hashes or hash-chain verification.
- **TypeScript package:** `@trisynapse/memory` is now `@trisynapse/trisynapse-memory`.
  - **Migration:** `npm install @trisynapse/trisynapse-memory` and update imports.

## 📦 Other Changes

- Optional extra: `pip install 'trisynapse-memory[tokens]'` for Tiktoken-backed counters. The `all` extra includes it.
- `scripts/version.py` maps PEP 440 prereleases to npm SemVer (`0.2.0rc1` → `0.2.0-rc.1`) and adds a `npm` subcommand.
- Engine internals are split into `formation`, `providers`, `recall`, `retrieval`, and `trace` packages. Public imports from `trisynapse_memory` are unchanged except as listed above.
